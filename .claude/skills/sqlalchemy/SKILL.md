# SQLAlchemy 2.0 (async ORM)

SQLAlchemy 2.0's ORM uses typed `Mapped[...]`/`mapped_column()` declarative models and a
unified `select()` statement style shared between Core and ORM. This project uses the
**async** extension (`AsyncSession`, `create_async_engine`) throughout — the sync APIs
(`Session`, `Query`) don't apply here.

## This repo's conventions

- Models live in `backend/app/models/<feature>.py`, subclass `Base` from
  `app.core.database`, use `Mapped[...]`/`mapped_column()` — see `app/models/project.py`
  and `app/models/user.py` for the canonical style (typed columns, `ForeignKey`,
  `relationship(..., back_populates=..., cascade=...)`).
- DB session dependency is `get_db` in `app/core/database.py` — one `AsyncSession` per
  request, `expire_on_commit=False`. Never instantiate a session outside this.
- Queries live in `app/services/<feature>.py` (or inline in thin route handlers for
  trivial lookups) — see `app/services/auth.py` for the `select()`/`scalar_one_or_none()`
  pattern.
- Migrations are in `backend/alembic/` (async-aware `env.py` already configured — see
  `references/alembic-migrations.md` before touching it).
- Dev DB is SQLite (`sqlite+aiosqlite`); production requires PostgreSQL — `Settings`
  enforces this (see `app/core/config.py`). Don't rely on SQLite-only behavior (e.g.
  loose typing, `AUTOINCREMENT` quirks) in code paths that matter.

## Quick start: model + query + write

```python
# app/models/widget.py
from datetime import UTC, datetime
from sqlalchemy import ForeignKey, String
from sqlalchemy.orm import Mapped, mapped_column, relationship
from app.core.database import Base

class Widget(Base):
    __tablename__ = "widgets"
    id: Mapped[int] = mapped_column(primary_key=True, index=True)
    name: Mapped[str] = mapped_column(String(200))
    owner_id: Mapped[int] = mapped_column(ForeignKey("users.id"), index=True)
    created_at: Mapped[datetime] = mapped_column(default=lambda: datetime.now(UTC))
```

```python
# app/services/widgets.py
from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession
from app.models.widget import Widget

async def list_widgets_for_owner(db: AsyncSession, owner_id: int) -> list[Widget]:
    result = await db.execute(select(Widget).where(Widget.owner_id == owner_id))
    return list(result.scalars().all())

async def create_widget(db: AsyncSession, owner_id: int, name: str) -> Widget:
    widget = Widget(owner_id=owner_id, name=name)
    db.add(widget)
    await db.commit()
    await db.refresh(widget)
    return widget
```

Then generate the migration:
```bash
cd backend && alembic revision --autogenerate -m "add widgets table"
# review the generated file before running:
alembic upgrade head
```

## Non-obvious gotchas worth knowing up front

- **Lazy-loaded relationships raise, not silently query, under `AsyncSession`.**
  Accessing an unloaded `relationship()` attribute outside `selectinload()`/eager-loading
  raises `MissingGreenlet`/`IllegalStateChangeError`, not a synchronous SQL round-trip.
  Always eager-load what you'll touch, or explicitly `await session.refresh(obj, ["rel"])`.
- **`expire_on_commit=False`** (already set in `app/core/database.py`) is required for
  async — without it, every attribute access after `commit()` tries to lazy-refresh and
  fails the same way. Don't remove it.
- **Alembic autogenerate cannot detect table/column *renames*** — it sees them as a
  drop+add pair, silently discarding data unless you hand-edit the migration. Always
  review autogenerated migrations before running `upgrade head`.
- **SQLite in dev vs PostgreSQL in prod** means some things that "work" locally
  (implicit type coercion, missing `NOT NULL` enforcement in edge cases) will behave
  differently in prod. Don't treat a passing local test as proof a migration/type is safe.
